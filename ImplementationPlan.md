**T3.2 done criterion, measurable form.** "120 Hz on a static desktop with CPU < 25 %" means:
(1) static desktop, no updates: **0 draws** (the display link is paused) and process CPU well under 25 % of one core;
(2) `-FramebufferDebug stream` (a 200 × 200 region repainted 120 times per second): draws at the display's maximum
rate (120 Hz on ProMotion, 60 Hz elsewhere) with CPU < 25 % of one core. Measured from `ps -o cputime=` deltas
over 5 s and the debug window's `draws/s` lines. Still to be measured live on an unlocked session (the first
measurement ran with the screen locked, so no frame could be drawn); 120 Hz needs a ProMotion display.

**T5.5 status.** Done (TRD › Security › Hostile server input). `ParserFuzzTests` (RFBKit) is a deterministic, seedable (SplitMix64, per-input seeds), structure-aware fuzzer over every parser of server bytes: the decoder vectors mutated field by field (`StreamIndex` field maps: extremes 0, 1, max, Int32.min, the caps ±1, length = bytes left ±1; bit flips, truncation at message boundaries, insert/delete/duplicate, splicing between vectors, message swaps, random chunking), grammar-generated decoder streams (every encoding, DesktopSize, ExtendedDesktopSize, Cursor, colour map, legacy and extended cut text, floods; hostile *plain* ZRLE tiles and Tight data compressed with real persistent zlib streams and the reset bits, so the tile and filter parsers are reached), handshakes for 3.3/3.7/3.8/3.889 and every security path with rotating credentials and hostile Apple DH groups (even, tiny, padded, all-ones primes; generator and public key 0, 1, p − 1, p, > p; key lengths 0, 513, 0xFFFF), chained into a decoder sized by ServerInit as `RFBConnection` does, the clipboard (ExtendedClipboard vectors mutated, caps/notify/request/peek/provide with hostile sizes, bombs, broken zlib, through `ClipboardNegotiation`), random bytes, `TightDecoder.measure` and `Inflater` round trips.
