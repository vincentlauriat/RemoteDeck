# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project status

**RemoteDeck** (provisional name): a native macOS client that opens screen sessions on remote Macs (Apple Remote Desktop / RFB-VNC protocol) and on Anthropic computer use environments (VNC). The skeleton was bootstrapped from `Templates/AppKitTemplate` (task T1.1); the template's demo `Item` files were replaced by the Library Window in T3.4.

## Commands

The Xcode project is generated by XcodeGen and git-ignored. Run `xcodegen generate` after any change to `project.yml`, and after adding or removing files.

```bash
xcodegen generate
xcodebuild -project RemoteDeck.xcodeproj -scheme RemoteDeck -derivedDataPath build/DerivedData build
xcodebuild -project RemoteDeck.xcodeproj -scheme RemoteDeck -derivedDataPath build/DerivedData test
cd Packages/RFBKit && swift test                                   # fastest loop for protocol work
cd Packages/RemoteDeckCore && swift test                           # models, Keychain, validation
cd Packages/ClaudeKit && swift test                                # Claude Assistant protocol side (fake HTTP only)
cd Packages/RFBKit && swift test --filter ProtocolVersionTests/parsesStandardBanner   # single test
RFBKIT_PERF=1 swift test --filter modPowTiming                    # opt-in timing tests and the 2000-run cancel-race stress (run from Packages/RFBKit)
cd Packages/RFBKit && RFBKIT_PERF=1 swift test -c release -Xswiftc -enable-testing --filter ParserFuzzTests   # full parser fuzz run (>1M inputs; the default run does ~20k); replay with RFBKIT_FUZZ_SEED / RFBKIT_FUZZ_START / RFBKIT_FUZZ_COUNT, RFBKIT_FUZZ_TRACE=1 names each input on stderr; under --sanitize=address add RFBKIT_FUZZ_SLOW_SECONDS=60 (a 4096-bit Apple DH input takes ~30 s there)
open "build/DerivedData/Build/Products/Debug/RemoteDeck Dev.app"   # Debug = bundle id …remotedeck.dev
"build/DerivedData/Build/Products/Debug/RemoteDeck Dev.app/Contents/MacOS/RemoteDeck Dev" -FramebufferDebug stream 2> fb.log &   # Debug-only synthetic framebuffer window (static | stream); draws/s, uploads/s, CPU time and system-shortcut tap state on stderr
"build/DerivedData/Build/Products/Debug/RemoteDeck Dev.app/Contents/MacOS/RemoteDeck Dev" -LibraryDemo session &   # Debug-only: Library Window on an in-memory sample library (list | editor | session | assistant | discovery | empty | store-error | discovery-empty | discovery-blocked | discovery-failed | onboarding | watch | history | resilience); in-memory passwords, fake Test connection, fake sessions (session: three tabs of one Session Window, "Mac mini" and "NAS" show a test pattern, "Studio" fails auth, a second Connect on "Mac mini" opens no fourth tab, then tab 2 is selected as ⌘2 does; assistant: one "Mac mini" session with the Claude Assistant Panel open, an in-memory demo key and scripted API answers, never a request) and fake Bonjour results (discovery*: opens the Discovery Panel, in its found/empty/blocked/failed state), empty: no sample machines, store-error: the in-memory banner, onboarding: the Onboarding Sheet (nothing persisted, fake notification answer), history: the Session History window over fixed in-memory records (every outcome, one older than 30 days, one left open by a "killed run" = Unknown duration, two of deleted machines, one name with a comma and quotes) plus a live fake "Mac mini" session = In progress, resilience: "Mac mini" and "NAS" drop 4 s after their first frame, "Mac mini" reconnects on its own, the automatic attempt of "NAS" fails to "Connection lost" (real path monitor and sleep/wake, fake connections; the other demo modes use neither), watch: status dots on fake probes every 3 s ("NAS" goes offline and back, "Build server" stays offline) with Status Notifications printed on stderr ("[LibraryDemo watch] notification: …"), never posted; no network, never the real store or Keychain, no Accessibility or notification prompt. A plain Debug launch (no switch) shows the real first-launch onboarding, whose last page opens the real Discovery Panel
```

The project targets Swift 6 language mode, so strict concurrency errors are build failures. Fix them with actor isolation (`@MainActor`, actors, `Sendable`), never by downgrading the language mode. Local builds are ad-hoc signed so the App Sandbox applies (`RemoteDeck/RemoteDeck.entitlements`). `Scripts/release.sh` re-signs with Developer ID, passes the same entitlements, and aborts if the sandbox entitlement is missing. iCloud/CloudKit is not configured yet: it needs a Developer ID provisioning profile from Vincent's Apple account.

## Architecture (planned)

- Swift 6, macOS 15+, SwiftUI for windows and sheets; an AppKit `NSView` backed by `CAMetalLayer` for the remote framebuffer and input capture.
- `RFBKit`: a local Swift package with no UI dependency. It handles the RFB protocol over `NWConnection`: auth types 1, 2 and 30 (Apple Diffie-Hellman), and the Raw/CopyRect/ZRLE/Tight decoders. `RFBHandshake` is a pure byte-driven state machine; `RFBConnection` (actor) drives it over TCP and runs each step on a dedicated queue so Apple DH modPow never blocks the cooperative pool. Tests use hand-built byte streams, Python/OpenSSL-generated vectors (`Tests/RFBKitTests/Vectors/generate_auth_vectors.py`) and an in-process `NWListener` fake server (`FakeRFBServer`: read its transcript with `received(within:)`, never `transcript.value`, which waits forever if the client fails before connecting; loopback suites carry `.timeLimit(.minutes(1))`); real captures go in `Tests/RFBKitTests/Captures/`.
  - Anthropic VM (T3.7): how to run the reference computer use container locally and the AC4 checklist are in `Tests/RFBKitTests/Captures/README.md`; `AnthropicVMLoopbackTests` is its Docker-free stand-in.
  - Fuzzing (T5.5): `ParserFuzzTests` (`FuzzSupport.swift`: SplitMix64, field-mapped `FuzzSample`, `Mutator`, `StreamIndex`; `FuzzCorpus.swift`: vector seeds and grammar generators) checks typed and sticky errors, buffered-byte and per-call copy bounds, chunking invariance and that applying the events reproduces the framebuffer; inputs it found are in `FuzzRegressionTests` with their bytes. A trap ends the test process: replay the range with `RFBKIT_FUZZ_TRACE=1`.
  - `rfb-probe` (executable target, not built by the app): `cd Packages/RFBKit && swift run rfb-probe <host> [--port N] [--user NAME --password-prompt | --password-env VAR | --wrong-password] [--capture DIR] [--frame FILE.png [--encodings tight,zrle,raw]]` checks a live server and records its server → client bytes only; `--frame` decodes the first full frame to a PNG (see `Tests/RFBKitTests/Captures/README.md`).
- Input: `InputTranslator` (RFBKit, pure: keysyms, modifier profile per machine kind, pointer mask, scroll steps, no stuck keys) and `InputSender` (ordered, off the main actor, coalesces mouse moves); the app's `SessionInputController` adapts NSEvents and owns the keyboard capture of `FramebufferView` (TRD › Input). Shortcut matchers are pure, in RFBKit (`ReleaseShortcut` ⌃⌥⌘R, `LocalShortcut` ⌘1…⌘9, `SystemShortcut`); `SystemShortcutTap` (app) is a session `CGEventTap` that takes system combos only while capturing with Accessibility trust, driven by the pure `SystemShortcutTapState`.
- `RemoteDeckCore` (local package): SwiftData models (`RemoteDeckSchemaV1` + migration plan), `RemoteDeckSchema.makeContainer` (stores `RemoteDeckLibrary.store` / `RemoteDeckHistory.store` under `Application Support/<bundle id>/`), `KeychainStore`, `MachineValidator`. `AppSettings` stays in the app (`Localization.swift`) and is tested by the hosted `RemoteDeckTests` target.
- Library (`RemoteDeck/Library`, `RemoteDeck/Views`): `MachineLibraryModel` (search, sections, delete with Keychain cleanup) and `MachineEditorModel` (fields, `MachineValidator`, Keychain-first save, Test connection with a 5 s timeout and a generation token against late results) are `@MainActor @Observable` and take their dependencies as protocols: `MachinePasswordStore` (`KeychainStore` in the app) and `ConnectionTester` (`RFBConnectionTester` = `RFBConnection.open` then `close`). Views call `settings.t`; models expose reasons/enums, never UI strings. `LibraryStore.isRunningTests()` makes the app open an in-memory container under XCTest. The hosted tests cannot run a loopback RFB server (the sandbox has no `network.server`), so they use `FakeConnectionTester`; RFB-level tests stay in RFBKit.
- Session Window (`RemoteDeck/Session`, `Views/SessionWindowView.swift`): `WindowGroup(id: "session", for: UUID.self)`, one window per machine (tabs are T4.2), never restored at launch. `SessionManager` (one `SessionModel` per machine id; `requestWindow` brings an open machine's window forward instead of a second window) and `SessionModel` (`@MainActor @Observable`: connect → first frame → connected, `SessionFailure` banners, Retry/Reconnect with a generation token, SessionRecord writing) take `SessionConnection` (`RFBConnection` in the app, `FakeSessionConnection` in tests), `SessionSurface` (`FramebufferView`), `MachinePasswordStore` and `SessionClock`. Stopping always runs `releaseCapture`/`tearDownInput` → `InputSender.finish()` → `stopped()` → `close()`, and never cancels the event loop first (that would close the socket under the releases).
- Discovery (`RemoteDeck/Discovery`): `DiscoveryService` (`@MainActor @Observable`, phases searching/found/empty/blocked/failed) takes a `BonjourBrowserFactory` (`NWBonjourBrowserFactory`: one `NWBrowser` per type) and a `BonjourResolver` (`DNSSDResolver`: `DNSServiceResolve` on the main queue, no connection); `DiscoveredMachine.merge` groups services per resolved host. It is built only when the Discovery Panel opens (`makeDiscovery`), so neither launch nor the hosted tests browse the network; tests use `FakeBonjourBrowsers`/`FakeBonjourResolver`. Local Network permission denied = browser waiting with kDNSServiceErr_PolicyDenied. `NSBonjourServices`/`NSLocalNetworkUsageDescription` live in `project.yml` › info; `network.client` is the only network entitlement needed (TRD › Security).
- Onboarding (`RemoteDeck/Onboarding`, `Views/OnboardingSheetView.swift`): `OnboardingLaunch` (pure) decides whether the sheet shows (off under XCTest, `-FramebufferDebug` and every `-LibraryDemo` mode but `onboarding`); `OnboardingModel` (`@MainActor @Observable`) runs the 3 pages and records `AppSettings.onboardingCompleted` once; notifications go through `NotificationAuthorizing` (`UserNotificationAuthorizer` in the app, a fake in tests and the demo) and are requested only on the button's click.
- Status Notifications (T4.5, TRD › Architecture › Reachability; `RemoteDeck/Reachability`): `ReachabilityMonitor` (`@MainActor @Observable`, one loop per watched `WatchTarget`, fed from the store by `WatchTargetFeed` on every `ModelContext.didSave` (not by a view); pure debounce in `WatchState`) takes a `ReachabilityProbe` (`TCPReachabilityProbe` → RFBKit `TCPProbe`: connect, close at once), a `ReachabilityClock` (interval, timeout race, wake grace), a `NetworkPathMonitoring` (`NWPathMonitor`) and a `NotificationPosting` (`UserNotificationPoster`; posts only when `notificationsEnabled` and authorized, never requests). Clicks: `StatusNotificationDelegate` (set in `App.init`) → `StatusNotificationRouter` → the Library Window (select; "back online" → Connect). The permission line and its "Allow notifications" button: `NotificationPermissionModel` + `NotificationPermissionNotice` (Settings, Machine Editor). Never started under XCTest or in demo modes but `watch`; tests use `FakeReachabilityProbe`/`FakeReachabilityClock`/`FakeNetworkPath`/`FakeNotificationPoster`, and real-socket probe tests live in RFBKit (`TCPProbeTests`).
- Clipboard (T4.1, TRD › Clipboard): `ClipboardNegotiation`/`ExtendedClipboard` (RFBKit, pure) do legacy Latin-1 cut text and the Extended Clipboard (UTF-8, zlib provide, caps/notify/request/peek answered inside `RFBConnection`, which only delivers `.serverCutText`); `RFBConnection.setClipboardSharing` (off by default) and `shareClipboard`. The app's `ClipboardBridge` reads `NSPasteboard` only while the session window is key (changeCount check on key + 0.5 s poll), skips concealed/transient/auto-generated items, guards against echo, and is tested on `InMemoryPasteboard` (never the real pasteboard; also used by `-LibraryDemo`). Never log clipboard contents. Vectors: `Tests/RFBKitTests/Vectors/generate_clipboard_vectors.py`.
- Session Tabs (T4.2, TRD › Architecture › Session Tabs): each session is its own `NSWindow` from the `WindowGroup(for: UUID.self)` scene, tabbed into one Session Window by `SessionTabs` (AppKit bridge: SwiftUI has no tabbing API). A session ends only on its window's `willClose` (`SessionWindowObserver`), never on `onDisappear`: tab switch, minimise, full screen and moving tabs keep it. ⌘1…⌘9: `SessionTabCommands` plus key-code matching in `FramebufferView` (AZERTY). Capture, tap and clipboard follow the key window, so the selected tab; background tabs pause the display link (`occlusionState`) but stay connected.
- Session History (T4.6, TRD › Architecture › Session History): the pure part is in RemoteDeckCore (`SessionHistory.swift`: `HistoryEntry` snapshots, `HistorySummary` 30-day maths with an injected `now`, `HistoryCSV`, `SessionHistory.rows`/`recentMachineIDs`, `HistoryRetention.purge`, run at launch on the on-disk store only). The app's `SessionHistoryModel` (filters, sort, Reconnect, Export through `HistoryExporting`; tests use a fake, never a save panel) and `Views/SessionHistoryView.swift` (`Window(id: "history")`, ⌘Y). "In progress" = the record id is in `SessionManager.liveRecordIDs`; an open record not in it is "Unknown" (never give it an end). `MenuBarContentView` (Menu Bar Extra, not inserted under XCTest) and the History's Reconnect go through `SessionLauncher.connect`, the Library's Connect path. Export needs the `files.user-selected.read-write` entitlement.
- Session resilience (T5.1, TRD › Architecture › Session resilience): `SessionModel.Phase.waiting(retryDelay | network | asleep)` = no attempt, no open record, last frame under the overlay; the automatic attempt is a normal `.connecting` with `isAutomaticAttempt`. A drop after the first frame → one attempt after `SessionResilience.reconnectDelay` (2 s, on an injected `ReachabilityClock`), then "Connection lost" (auth failures keep their banner; 60 s re-arm rule, never a loop). `SessionManager` owns a separate `NetworkPathMonitoring` and the `NSWorkspace` sleep/wake observers (injected center; both nil under XCTest) and fans out `networkLost`/`networkRestored`/`suspendForSleep`/`resumeAfterWake` (after the 5 s wake grace). `suspend` bumps the generation before the teardown (so the stream ending is not a drop) and stops the assistant first; pending tasks check `reconnectToken` and `Task.isCancelled` after every await. A path loss closes a connected session only after `pathLossGrace` (3 s). Automatic attempts read the Keychain with `allowsInteraction: false`. RFBKit `ConnectionLiveness` (TCP keepalive + `ViabilityWatchdog`) is on every `RFBConnection`. `SessionManager.stop()` in tests. Tests: `SessionResilienceTests` with `FakeReachabilityClock` (wait for `pending(...)` before `fire`, or the sleep is not registered yet), `FakeNetworkPath`, a private `NotificationCenter`.
- UI strings: add every key to both `fr` and `en` in `Localization/Strings.swift` (`StringsTests` checks the key sets match); `settings.t(key, arg)` fills `%@`/`%d`.
- SwiftData with two stores: Machine and MachineGroup are synced through CloudKit (private database); SessionRecord and AssistantAction stay local. CloudKit rules apply: optional or defaulted properties, no unique constraints, additive schema changes only.
- All secrets live in the Keychain only: machine passwords are synchronizable items (with a local-item fallback on -34018 until the entitlement exists; T4.3 migrates them), the Anthropic API key is local-only. An in-memory library uses `InMemoryPasswordStore`.
- Claude Assistant (T4.4, TRD › Claude Assistant): `ClaudeKit` (local package, depends on RFBKit, no UI) holds the raw-HTTP Messages API client (`MessagesClient`, `HTTPTransport`; no Anthropic Swift SDK exists), the append-only `Conversation` (assistant blocks replayed with the API's original bytes, `RawJSON`; own blocks sorted-key; every `tool_use` answered whatever the stop reason, deferred results open the next user message), `ComputerAction`/`ActionPlanner` (toolset member → RFB messages, nothing held after a plan) and `ImageLimits`/`ScreenMapping`/`ScreenshotEncoder`; key names → keysyms is `KeyChord` (RFBKit). Model `claude-opus-5-5` with `computer_toolset_20260801` (no name, no display size, `left_mouse_down`/`up` withheld), `thinking: {adaptive, display: "updates"}` + beta header, effort `medium`, top-level `cache_control`. `AssistantModel` (app, `@MainActor @Observable`, one per session via `SessionManager.makeAssistant`, `SessionModel` is its `AssistantSessionPort`) runs on demand only: screenshot/zoom/cursor_position/wait run alone, every other action waits for Confirm (by tool_use id, armed after 400 ms, no key repeat), Skip or Stop (`stopping` until the task settles); input goes through `SessionModel.assistantSend` → `InputSender`, and the view's non-release input is held back while an action runs, and `sessionEnded()` runs in `beginClose`/`stop` before the teardown releases. The API key is set only by `APIKeyEditorModel` (prefix, `GET /v1/models` check, then `AppSettings.storeAPIKey`), through `APIKeyStore` (Keychain in the app, `InMemoryAPIKeyStore` under XCTest and in the demo). Tests never call the API (fake `HTTPTransport`) nor touch the Keychain.
