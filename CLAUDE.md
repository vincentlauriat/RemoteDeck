# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project status

**RemoteDeck** (provisional name): a native macOS client that opens screen sessions on remote Macs (Apple Remote Desktop / RFB-VNC protocol) and on Anthropic computer use environments (VNC). The skeleton was bootstrapped from `Templates/AppKitTemplate` (task T1.1). The demo `Item`, `ItemsViewModel` and `Item*View` files are template leftovers, to be replaced in step 3.

## Commands

The Xcode project is generated by XcodeGen and git-ignored. Run `xcodegen generate` after any change to `project.yml`, and after adding or removing files.

```bash
xcodegen generate
xcodebuild -project RemoteDeck.xcodeproj -scheme RemoteDeck -derivedDataPath build/DerivedData build
xcodebuild -project RemoteDeck.xcodeproj -scheme RemoteDeck -derivedDataPath build/DerivedData test
cd Packages/RFBKit && swift test                                   # fastest loop for protocol work
cd Packages/RemoteDeckCore && swift test                           # models, Keychain, validation
cd Packages/RFBKit && swift test --filter ProtocolVersionTests/parsesStandardBanner   # single test
RFBKIT_PERF=1 swift test --filter modPowTiming                    # opt-in timing tests (run from Packages/RFBKit)
open "build/DerivedData/Build/Products/Debug/RemoteDeck Dev.app"   # Debug = bundle id …remotedeck.dev
```

The project targets Swift 6 language mode, so strict concurrency errors are build failures. Fix them with actor isolation (`@MainActor`, actors, `Sendable`), never by downgrading the language mode. Local builds are ad-hoc signed so the App Sandbox applies (`RemoteDeck/RemoteDeck.entitlements`). `Scripts/release.sh` re-signs with Developer ID, passes the same entitlements, and aborts if the sandbox entitlement is missing. iCloud/CloudKit is not configured yet: it needs a Developer ID provisioning profile from Vincent's Apple account.

## Architecture (planned)

- Swift 6, macOS 15+, SwiftUI for windows and sheets; an AppKit `NSView` backed by `CAMetalLayer` for the remote framebuffer and input capture.
- `RFBKit`: a local Swift package with no UI dependency. It handles the RFB protocol over `NWConnection`: auth types 1, 2 and 30 (Apple Diffie-Hellman), and the Raw/CopyRect/ZRLE/Tight decoders. `RFBHandshake` is a pure byte-driven state machine; `RFBConnection` (actor) drives it over TCP and runs each step on a dedicated queue so Apple DH modPow never blocks the cooperative pool. Tests use hand-built byte streams, Python/OpenSSL-generated vectors (`Tests/RFBKitTests/Vectors/generate_auth_vectors.py`) and an in-process `NWListener` fake server; real captures go in `Tests/RFBKitTests/Captures/`.
  - `rfb-probe` (executable target, not built by the app): `cd Packages/RFBKit && swift run rfb-probe <host> [--port N] [--user NAME --password-prompt | --password-env VAR | --wrong-password] [--capture DIR]` checks a live server and records its server → client bytes only (see `Tests/RFBKitTests/Captures/README.md`).
- `RemoteDeckCore` (local package): SwiftData models (`RemoteDeckSchemaV1` + migration plan), `RemoteDeckSchema.makeContainer`, `KeychainStore`, `MachineValidator`. `AppSettings` stays in the app (`Localization.swift`) and is tested by the hosted `RemoteDeckTests` target.
- SwiftData with two stores: Machine and MachineGroup are synced through CloudKit (private database); SessionRecord and AssistantAction stay local. CloudKit rules apply: optional or defaulted properties, no unique constraints, additive schema changes only.
- All secrets live in the Keychain only: machine passwords are synchronizable items, the Anthropic API key is local-only.
- The Claude Assistant uses the Anthropic Messages API with the computer use tool. It runs on demand only, and the user confirms every action before it is sent as RFB input.
